# 🧠 ANALOGY REGISTER — Every Analogy Ever Used, Numbered

> **Why this exists:** analogies are the series' superpower and its biggest reuse risk. Every analogy gets a **stable number** recorded here (analogy, concept it teaches, day it appeared). The next chapter's input carries the **last ~5 chapters' entries**, and the writer must avoid **all supplied entries — especially the last 20**. Every analogy in a chapter must ship with a "⚠️ Where the analogy breaks" note; that note is *not* logged here, only the analogy + concept + day.
>
> **Update rule:** append new entries at the end of the table and bump `last-entry`. Never renumber. When supplying the next chapter's input, copy the trailing rows for the last ~5 written days.

## Rules (mirrored from [[fde by onepiece/00 Master Prompt|00 Master Prompt §2.6]])

1. Numbered, stable IDs, append-only — never renumber or edit old entries.
2. Chapter input carries ~5 chapters of entries; the writer avoids every supplied entry, with extra weight on the last 20.
3. If fewer than 20 entries exist, avoid all of them.
4. Never claim an analogy is "globally new" when older entries weren't supplied — say "new to the supplied register."
5. Reusing an analogy for the **same concept as reinforcement** is allowed only if explicitly labeled a callback ("remember Day 12's…") — a *fresh analogy for a fresh concept* is the default.
