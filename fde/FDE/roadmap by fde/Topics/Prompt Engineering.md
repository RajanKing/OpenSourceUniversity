# Prompt Engineering

[[roadmap by fde/00 Start Here|Start Here]] / [[roadmap by fde/Tracks/04 AI Engineering|04 AI Engineering]] / [[roadmap by fde/01 Complete Topic Index|Complete Topic Index]]

## Meaning and FDE Relevance

Prompt engineering specifies a task, constraints, examples, and output expectations so that model behavior can be tested.

## Concepts to Understand

- Separate instructions from untrusted data.
- Specify an output schema.
- Use representative examples.
- State abstention and escalation rules.
- Version prompt changes.
- Compare on held-out cases.

## Applied Exercise

Create an extraction prompt with a JSON schema and evaluate it on missing, conflicting, and adversarial inputs.

Use synthetic data and sandbox services. Do not connect customer systems, spend provider credits, or change production data without explicit authorization.

## Common Failure Mode

Adding more instructions after each anecdotal failure until the prompt becomes contradictory.

## Evidence of Mastery

A prompt revision improves measured outcomes without breaking existing cases or weakening boundaries.

- [ ] Explain the concepts and tradeoffs without reading the notes.
- [ ] Complete the exercise and retain a reproducible artifact.
- [ ] Test an error, permission, or recovery case where applicable.
- [ ] Record an observation, limitation, and next improvement.
