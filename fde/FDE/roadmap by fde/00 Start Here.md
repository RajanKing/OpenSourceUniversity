## A Practical Learning Order

Begin with role orientation and a real workflow problem. Build a thin full-stack slice before introducing agent autonomy. Learn enough data engineering to trust your inputs. Add retrieval and model evaluation, then bounded tools only when the task requires actions. Establish authorization, operational ownership, and business measurements before calling the result production-ready.

Discovery, communication, privacy, and security run throughout this sequence. Their placement near the bottom of a roadmap does not mean they should begin after implementation.

Choose one primary programming language, one frontend approach where necessary, and one cloud platform. Java, Scala, Go, Rust, C++, and every listed coding assistant are alternatives or context-dependent specialties, not prerequisites that must all be mastered before delivering a useful system.

## What Each Topic Contains

Each topic includes an original definition, concrete concepts, an applied exercise, a failure mode, observable mastery evidence, the original roadmap resources, local source notes, and links to neighboring topics. Checkboxes and the `status` property are for your study progress; no Dataview or other plugin is required.

Keep an artifact for each completed topic: a design, test, dataset audit, measured result, runbook, or user-acceptance record. Watching a course is an input to learning, not the proof that you can deliver.

## Source and Completeness Boundary

All 94 topic resource responses were retrieved. The folder retains 317 distinct topic-resource URLs plus 14 additional graph destinations, for 331 total. The direct-resource audit found 208 pages with readable metadata, 100 video landing pages without reviewed transcripts, 16 HTTP errors, five request failures or timeouts, one HTML page without readable headings, and one invalid or non-HTTP original URL.

The 331 source notes are primarily access records and topic-specific reading agendas. They are not 331 full-content summaries. Selected accessible sources were read in more detail and summarized separately. No entire third-party site, paid course, video, or book has been copied. Links inside external sites were not recursively crawled. See the coverage report before treating any source as verified or exhaustive.

The newer Markdown export separately expands all 44 directly linked roadmap graphs and topic-resource lists. It imports their links without claiming that all external destinations were content-reviewed. Further roadmaps beyond this one-hop scope remain external links. The original 331-link audit applies only to the main FDE resource set.

## Regeneration Warning

The `tools` folder contains optional reproducibility scripts; `Sources` contains structured manifests and access results. The notes, Markdown roadmaps, and canvases work without running any scripts. Publishing overwrites generated content, so preserve personal edits before regeneration. Network extraction is a separate operation. No Obsidian settings were changed.

For the new Markdown export, `Build-MarkdownRoadmap.ps1` separates cached graph extraction (`-ExtractGraphs`), resumable topic-resource import (`-Extract`), offline publication (`-Publish`), and coverage validation (`-Validate`).
